0. CROSS-CUTTING FINDINGS (the things that shape the design)
======================================================================
A. Every CLI now has a hook system that pipes JSON to a subprocess (Claude: also `type:"http"` POST hooks; Codex: command or MCP-tool hooks; Gemini: command hooks). Hooks give STATE and QUESTIONS reliably and cheaply; none of the three hook systems can inject free text into a running interactive session. Hooks CAN answer questions in Claude (PermissionRequest decision; AskUserQuestion via PreToolUse allow+updatedInput; Elicitation accept/content) and can answer permission prompts in Codex (PermissionRequest allow/deny only). Gemini hooks are advisory for permissions (Notification/ToolPermission) except BeforeTool decision (allow/deny/block/ask — interactive bypass unverified).
B. The only SUPPORTED live-injection paths into an operator-visible interactive session are: Claude Code "channels" (MCP server declaring `claude/channel`, research preview, allowlist/auth gated) and Codex app-server `turn/steer`/`turn/start` when the TUI is attached to a daemon-owned app-server via `codex --remote`. Gemini has none. Everything else is terminal-keystroke injection (tmux send-keys, iTerm2 Python API, Terminal.app AppleScript, CGEvent) — robust enough as fallback because all three CLIs read the prompt line from the tty.
C. Terminal identity for the fallback is best captured at SessionStart from the hook's inherited environment (Claude docs: hook process inherits the parent environment; `TMUX_PANE`, `ITERM_SESSION_ID`, `TERM_SESSION_ID`, `$PPID`→ `ps -o tty=`), not by parsing window titles. Title parsing is a last resort: Gemini (◇/✋/✦ glyphs, on by default) and Codex (`[ ! ] Action Required`, configurable `session_id` item) are parseable; Claude's title is a free-form `repo · topic · session-id` (community-reported) with no state glyph. On macOS, `kCGWindowName` requires Screen Recording permission; AX `AXTitle` requires Accessibility permission.
D. Daemon-HOSTED sessions (our process owns the agent, gpui GUI is the surface) get a real programmatic input channel on all three: Claude `claude -p --input-format stream-json --output-format stream-json --permission-prompt-tool stdio` (control_request/control_response envelope documented in the Agent SDK TS reference; `pending_permission_requests` on initialize ≥ v2.1.268) or the Agent SDK; Codex `codex app-server` (stdio JSONL, `thread/*`, `turn/*`, server-initiated approval/requestUserInput requests); Gemini `gemini --acp` (ACP JSON-RPC over stdio). ACP is also available for Claude (`@agentclientprotocol/claude-agent-acp`, Agent-SDK based) and Codex (`agentclientprotocol/codex-acp`, app-server based) → one uniform driver abstraction if we accept Node adapters.
E. Claude Code additionally ships `claude agents --json` (lists EVERY live session incl. `kind: interactive`, `pid`, `status: busy|waiting|idle`, `waitingFor: permission prompt|input needed|sandbox request|worker request|dialog open`, `sessionId`, `name`, `cwd`) — a zero-config roster/liveness cross-check, poll-based.

1.1 Hook events (full list from the reference): SessionStart, Setup, UserPromptSubmit, UserPromptExpansion, PreToolUse, PermissionRequest, PermissionDenied, PostToolUse, PostToolUseFailure, PostToolBatch, Notification, MessageDisplay, SubagentStart, SubagentStop, TaskCreated, TaskCompleted, Stop, StopFailure, TeammateIdle, InstructionsLoaded, ConfigChange, CwdChanged, DirectoryAdded, FileChanged, WorktreeCreate, WorktreeRemove, PreCompact, PostCompact, PreModelSwitch, PostModelSwitch, Elicitation, ElicitationResult, SessionEnd.
1.2 Common stdin JSON: `session_id`, `prompt_id` (≥2.1.196), `transcript_path` (async-written, may lag), `cwd`, `scratchpad_dir` (≥2.1.257), `permission_mode` (default|plan|acceptEdits|auto|dontAsk|bypassPermissions), `effort.level`, `hook_event_name`, `agent_id`/`agent_type` (subagents only). Env: `$CLAUDE_PROJECT_DIR`, `$CLAUDE_EFFORT`, `$CLAUDE_CODE_REMOTE`, `$CLAUDE_CODE_BRIDGE_SESSION_ID` (≥2.1.199); hook inherits parent env minus `OTEL_*`.
1.3 Hook types: `command` (shell or exec form; `async:true` fire-and-forget; `asyncRewake`), `http` (POST JSON body to `url`, response body = same JSON output shape, only 2xx counts; optional `allowedHttpHookUrls` allowlist), `mcp_tool`, `prompt`, `agent`. Default timeout 600 s (30 s on UserPromptSubmit/PreModelSwitch/PostModelSwitch; 10 s MessageDisplay; SessionEnd 1.5 s budget). Config merges across ~/.claude/settings.json (user), .claude/settings.json, settings.local.json, plugins.
1.4 State-relevant payloads:
 • Notification matchers: `permission_prompt` (fires only after ~6 s of no typing; in SDK-hosted sessions such as Claude Desktop/VS Code fires ~6 s after ask, ≥2.1.233), `idle_prompt` (~60 s after Claude finished, no typing since), `auth_success`, `elicitation_dialog`, `elicitation_url_dialog`, `elicitation_complete`, `elicitation_response`, `agent_needs_input`/`agent_completed` (agent view, ≥2.1.198), `quota_auto_resume_*` (≥2.1.234). Notification hooks cannot block; `systemMessage`/`continue` discarded; `terminalSequence` honored.
 • PermissionRequest: fires the moment a permission prompt is about to be shown (use this, not Notification, for the 🟥 state); input `tool_name`, `tool_input`, optional `mcp_server`, `permission_suggestions[]` (addRules/setMode… entries). Output `hookSpecificOutput.decision = {behavior:"allow", updatedInput?, updatedPermissions?} | {behavior:"deny", message, interrupt?}`; exit 2 without decision is ignored; if no hook decides, normal terminal prompt continues. Not fired for sandbox network prompts (use Notification permission_prompt).
 • PreToolUse matcher `AskUserQuestion`: `tool_input.questions[]` = {question, header (≤12 chars), options[2-4]{label, description}, multiSelect}; 1-4 questions per call. Answer by returning `hookSpecificOutput.permissionDecision:"allow"` + `updatedInput:{questions:<echo>, answers:{"<question text>":"<label or free text>"}}` (multi-select: array or ", "-joined; optional `response` for a general free-text reply). Docs state the allow+updatedInput path "so the tool runs without prompting"; precedence deny > defer > ask > allow. `"defer"` (‑p only) exits with `stop_reason:"tool_deferred"` + `deferred_tool_use{id,name,input}` and resumes with `claude -p --resume <id>`.
 • Elicitation (MCP form/url): input `mcp_server_name`, `message`, `mode`, `requested_schema`, `elicitation_id`; output `hookSpecificOutput{action: accept|decline|cancel, content}`.
 • Stop: `stop_hook_active`, `last_assistant_message` (text of final reply — documented as the field to use for read-aloud instead of the transcript), `background_tasks[]`, `session_crons[]`. Exit 2 / `decision:"block"` forces continuation (max 8). Not fired on user interrupt.
 • StopFailure: `error` ∈ rate_limit|overloaded|authentication_failed|oauth_org_not_allowed|account_on_hold|billing_error|invalid_request|model_not_found|server_error|max_output_tokens|cloud_credential_error|unknown, `error_details`, `last_assistant_message` (= the error string) → 🟠 Error.
 • UserPromptSubmit: `prompt` → 🟦 Working start. SessionStart matcher startup|resume|clear|compact|fork; SessionEnd matcher clear|resume|logout|prompt_input_exit|other → ⬜ Idle/gone.
 • MessageDisplay: streaming assistant text in `delta` with `turn_id`,`message_id`,`index`,`final` (display-only; in ‑p mode one call per message).
 • SubagentStop: `agent_id`, `agent_type`, `agent_transcript_path`, `last_assistant_message`.
 • `terminalSequence` output field (OSC 0/1/2/9/99/777 + BEL only) lets a hook set the window title/bell through Claude's own tty write path — usable to stamp a deterministic title.
1.5 statusLine (`~/.claude/settings.json` → `statusLine:{type:"command",command,refreshInterval?}`) receives JSON on stdin at every state change (debounced 300 ms; optional `refreshInterval` ≥1 s): `cwd`, `session_id`, `session_name`, `prompt_id`, `transcript_path`, `model{id,display_name}`, `workspace{current_dir,project_dir,added_dirs,git_worktree,repo}`, `version`, `cost{total_cost_usd,total_duration_ms,total_lines_added/removed}`, `context_window{used_percentage,…}`, `exceeds_200k_tokens`, `prompt_cache{…}`. Only one statusLine command per settings level → the daemon's statusline script must chain the user's own.
1.6 Session identity/resume: transcripts at `~/.claude/projects/<cwd-with-non-alnum→->/<session-id>.jsonl`; `claude --resume <id|name|transcript path>`, `--continue`, `--fork-session`, `--session-id <uuid>`, `--name` (shown in `/resume` and terminal title; `terminalTitleFromRename` setting), `--bg` (background session under a supervisor), `claude attach <id>`, `claude logs <id>`, `claude stop <id>`, `claude daemon status`, `claude agents --json [--all] [--cwd]`.
1.7 Free-text injection into a RUNNING interactive session:
 (a) Channels (research preview): an MCP server with `capabilities.experimental['claude/channel']:{}` emits `notifications/claude/channel {content, meta{identifier keys}}`; text lands in the live session as a `<\channel source=…>` event Claude acts on. Session must be started with `--channels plugin:<name>@<marketplace>` (Anthropic-curated allowlist) or `--dangerously-load-development-channels server:<mcp-name>` for a custom server; requires claude.ai or Console auth (not Bedrock/Vertex/Foundry); Team/Enterprise need `channelsEnabled`; flags hidden from `--help`; contract may change. Two-way channels expose a `reply` tool. Permission relay: declare `claude/channel/permission:{}`, receive `notifications/claude/channel/permission_request {request_id, tool_name, description, input_preview}` (≥2.1.211 sanitized ≤3,500 code points), answer with `notifications/claude/channel/permission {request_id, behavior:'allow'|'deny'}`; terminal dialog and remote both stay live, first answer wins. In `-p` mode AskUserQuestion/plan approval are disabled when channels are on.
 (b) Remote Control (`claude --remote-control`, `/rc`, `claude remote-control`): claude.ai / mobile app only; outbound HTTPS polling; Pro/Max/Team/Enterprise, no API keys; no third-party API. A reverse-engineering write-up (Origin, 2026-04-01) documents `--sdk-url` + NDJSON `control_request`/user messages — unsupported, do not build on it.
 (c) IDE protocol (`~/.claude/ide/<port>.lock`, `CLAUDE_CODE_SSE_PORT`, `ENABLE_IDE_INTEGRATION`, WebSocket MCP with `x-claude-code-ide-authorization`): IDE→CLI notifications are only `selection_changed` and `at_mentioned`; no text-input channel (claudecode.nvim PROTOCOL.md, community reverse-engineering).
 (d) Daemon-hosted: `claude -p --input-format stream-json --output-format stream-json --verbose --permission-prompt-tool stdio` — stdin `{"type":"user","message":{"role":"user","content":[…]}}`; stdout `{"type":"control_request","request_id","request":{"subtype":"can_use_tool","tool_name","input","decision_reason","tool_use_id"}}`; stdin `{"type":"control_response","response":{"subtype":"success","request_id","response":{"behavior":"allow","updatedInput":…}|{"behavior":"deny","message"}}}` (community-documented shapes; the envelope, `request_id` echo, `pending_permission_requests`, interrupt receipt `interrupt_receipt_v1` are in the official SDK TS reference). Or use `@anthropic-ai/claude-agent-sdk` streaming input + `canUseTool` (AskUserQuestion arrives in canUseTool with toolName "AskUserQuestion"; answer with `{behavior:"allow", updatedInput:{questions, answers}}`; `interrupt()`; `resume`/`continue`/`forkSession`). Trade-off: the operator's terminal is not the surface; the gpui GUI must render the transcript, or the operator later `claude --resume`s the session in a terminal (not concurrently).
 (e) Terminal injection (fallback): see §4.
1.8 Latency/robustness: PermissionRequest/PreToolUse/Stop are synchronous and immediate (sub-100 ms plus process spawn for command hooks; HTTP hooks avoid the spawn). Notification permission_prompt +≈6 s, idle_prompt +≈60 s. Hooks block Claude while running (600 s default) — holding a PermissionRequest/AskUserQuestion HTTP request open until the deck answers is possible but suppresses the terminal dialog meanwhile (verify; see open questions). Use `async:true` for pure reporting hooks. All configurable at user level (~/.claude/settings.json) → zero per-project setup.

2.1 Hooks: enabled by `features.hooks` (`features.codex_hooks` deprecated alias; requirements.toml can force); files `~/.codex/hooks.json` or `[hooks]` tables in `~/.codex/config.toml`, then `<repo>/.codex/hooks.json` (trusted layer only), plugin hooks. Events: SessionStart(source startup|resume|clear|compact), SessionEnd (archive/delete/idle 30 min; reason always `other`), PreToolUse, PermissionRequest, PostToolUse, PreCompact, PostCompact, UserPromptSubmit(prompt), SubagentStart, SubagentStop(last_assistant_message), Stop, Interrupt (main thread only, 1-3 s timeout). Common stdin: `session_id`, `transcript_path|null`, `cwd`, `hook_event_name`, `model`; turn-scoped add `turn_id`; tool hooks add `tool_name` (Bash, apply_patch (=Edit/Write), `mcp__server__tool`, function names e.g. update_plan, spawn_agent=Agent), `tool_use_id`, `tool_input` (`.command` for Bash/apply_patch; `.description` sometimes), `permission_mode`. Outputs: PreToolUse `hookSpecificOutput{permissionDecision allow|deny(|block), permissionDecisionReason, additionalContext, updatedInput (allow only)}`; PermissionRequest `hookSpecificOutput.decision{behavior:allow|deny, message}` ONLY (updatedInput/updatedPermissions/interrupt fail closed); deny wins; if no hook decides the normal TUI prompt appears; Stop `stop_hook_active`, `last_assistant_message|null`, `decision:"block"+reason` = continuation prompt; `continue:false`; systemMessage. Exit 2 = block with stderr reason. Default timeout 600 s. Hooks run with session cwd. `hooks/list` app-server method lists discovered hooks. No user-question hook: `tool/requestUserInput` is app-server-only.
2.2 notify: `notify = ["prog", …]` (user-level config only; ignored in project .codex/config.toml). Program receives ONE JSON argument (argv[1], not stdin): `{"type":"agent-turn-complete","thread-id","turn-id","cwd","client":"codex-tui"(seen in tests),"input-messages":[…],"last-assistant-message":"…"}`; only `agent-turn-complete` is emitted. `tui.notifications` (bool|["agent-turn-complete","approval-requested"]) emits OSC 9 / BEL to the terminal (`tui.notification_method auto|osc9|bel`, `tui.notification_condition unfocused|always`) — a terminal-side signal only.
2.3 app-server (`codex app-server`; JSON-RPC 2.0 without the "jsonrpc" key; transports `--listen stdio://` (default JSONL), `ws://IP:PORT` (documented "experimental and unsupported"; auth via `--ws-auth capability-token|signed-bearer-token`), `unix://`, `off`; `codex --remote ws://|wss://|unix://` attaches the TUI to a running app-server; schemas via `codex app-server generate-ts|generate-json-schema`). Handshake: `initialize{clientInfo, capabilities{experimentalApi, optOutNotificationMethods}}` → `initialized`. Threads: `thread/start` (auto-subscribes the connection), `thread/resume{threadId}`, `thread/fork`, `thread/list{cwd, archived, searchTerm…}` (returns id, preview, name, status{type: notLoaded|idle|active{activeFlags e.g. waitingOnApproval}|systemError}), `thread/read`, `thread/loaded/list`, `thread/name/set`, `thread/goal/*`, `thread/unsubscribe` ("if this was the last subscriber the server unloads the thread" → multi-subscriber per thread implied), `thread/archive|unarchive|delete`, `thread/inject_items`, `thread/compact/start`. Turns: `turn/start{threadId, input[{type:text,…}], cwd, model, effort, sandboxPolicy, approvalPolicy}`, `turn/steer{threadId, input, expectedTurnId}` (append to the in-flight turn, no new turn/started, fails if no active turn), `turn/interrupt`. Notifications: `thread/started|closed|archived|status/changed`, `turn/started`, `turn/completed{turn.status completed|interrupted|failed, error{message, codexErrorInfo e.g. UsageLimitExceeded}}`, `turn/diff/updated`, `turn/plan/updated`, `item/started`, `item/completed` (item types userMessage, agentMessage{text, phase}, commandExecution, fileChange, mcpToolCall, webSearch, reasoning, contextCompaction, dynamicToolCall…), `item/agentMessage/delta`, `item/commandExecution/outputDelta`, `serverRequest/resolved{threadId, requestId}`. Server→client REQUESTS (the "question" channel): `item/commandExecution/requestApproval{itemId, threadId, turnId, command, cwd, reason, additionalPermissions?, networkApprovalContext?}` → `{decision: accept|acceptForSession|decline|cancel|{acceptWithExecpolicyAmendment:{execpolicy_amendment:[…]}}}`; `item/fileChange/requestApproval` → accept|acceptForSession|decline|cancel; `item/permissions/requestApproval` (experimental) → grant|deny; `item/tool/requestUserInput` (experimental; 1-3 questions with options, `isOther` free-form) → `{answers:[…]}`; `mcpServer/elicitation/request` → `{formSubmission}`. Pending requests are cleared on turn start/complete/interrupt (serverRequest/resolved). `account/updated`, `model/list`, `hooks/list`, `command/exec/*`, `fs/*` also exist. Which subscriber receives server-initiated requests when several connections subscribe is NOT documented.
2.4 Terminal title: `tui.terminal_title` ordered item ids, default `["spinner","project"]` (`spinner`→`activity`, `project`→`project-name` canonical; also thread name, `model`, `session_id`, `branch`), `null` disables; `/title` picker. While approval/input overlays are active the title shows `[ ! ] Action Required` alternating with `[ . ] Action Required` and the spinner is suppressed (PR #18372 merged 2026-04-27). `tui.status_line` items similar. Sessions persisted as JSONL rollouts under `$CODEX_HOME` (history at `~/.codex/history.jsonl`; sessions dir referenced by thread/archive docs).
2.5 Desktop (ChatGPT/Codex app): uses app-server internally ("Desktop hosts" mentioned for attestation); `.codex/hooks.json` hooks ran in Desktop before 0.129.0-alpha.15; no documented external listener/API; `codex --remote` connects a TUI to an app-server you start, not to the Desktop app.

3.1 Hooks (settings.json `hooks`, user ~/.gemini/settings.json or project .gemini/settings.json; `hooksConfig.enabled` default true, `hooksConfig.disabled[]`, `hooksConfig.notifications`): events BeforeTool(tool_name, tool_input, mcp_context), AfterTool(tool_response{llmContent, returnDisplay, error}), BeforeAgent(prompt), AfterAgent(prompt, prompt_response, stop_hook_active), BeforeModel/AfterModel(llm_request/llm_response), BeforeToolSelection, SessionStart(source startup|resume|clear), SessionEnd(reason exit|clear|logout|prompt_input_exit|other), Notification(notification_type — ONLY `ToolPermission` in types.ts — plus `message`, `details`), PreCompress(trigger). Notification & PreCompress are observability-only. No AskUser-style question tool documented; no error hook (AfterAgent only).

3.3 Programmatic: headless `gemini -p|--prompt` (stdin appended), `--output-format text|json|stream-json` (events init, message, tool_use, tool_result, error, result), `--approval-mode default|auto_edit|yolo|plan`, `--resume latest|<index>|<uuid>`, `--list-sessions`; exit codes 0/1/42/53. No "send message to a running interactive session" feature exists.

4. GENERIC FALLBACK: window titles + tmux + macOS
======================================================================
• tmux (`man tmux`, man.openbsd.org/tmux): `tmux list-panes -a -F '#{pane_id} #{pane_pid} #{pane_tty} #{pane_current_command} #{pane_current_path} #{pane_title}'` (`pane_title` = the OSC title the program set, subject to `allow-set-title`; `set-titles` propagates to the outer terminal); `tmux capture-pane -p -J -S -60 -t %N` (screen text); `tmux pipe-pane -o -t %N 'cat >> file'` (live output stream); control mode `tmux -CC` gives `%output` notifications; `tmux send-keys -t %N -l '<text>'` then `send-keys -t %N Enter` (‑l = literal UTF-8, no key-name lookup). Map a CLI to a pane via the `TMUX_PANE` env the CLI (and its hooks) inherit, or by walking `pane_pid`'s process tree. tmux is not installed on this Mac today (checked).
• Terminal titles: Claude emits OSC 0 `repo-name · topic-summary · session-id` on state changes (community issue #47397, Apr 2026), `--name`/`/rename` names shown in title (`terminalTitleFromRename`), `CLAUDE_CODE_DISABLE_TERMINAL_TITLE=1` (incomplete on some versions); Codex default `spinner,project`, `[ ! ] Action Required`; Gemini ◇/✋/✦. Only Gemini and Codex carry a state glyph; Claude's title is NOT a reliable state source.
• macOS: `CGWindowListCopyWindowInfo` omits `kCGWindowName` without Screen Recording permission (macOS ≥10.15); Accessibility API (`AXUIElementCopyAttributeValue` on `AXWindows`/`AXTitle`, `AXFocusedWindow`, raise/focus) needs Accessibility permission; posting keystrokes (CGEventPost) also needs Accessibility. iTerm2 Python API (must be enabled in iTerm2 preferences): `Session.async_send_text(text)` ("as though the user had typed"; use `\r` for Enter), `Session.session_id`, `async_get_variable('id'|'name'|'autoName'|'jobName'|'path'|'tty'|'commandLine'|'pid')`, `async_get_screen_contents()`; the `ITERM_SESSION_ID` env var identifies the session (format `w0t0p0:UUID` — mapping to `session_id` is likely but not confirmed in the fetched page). Terminal.app AppleScript `do script "<text>" in <tab>` sends text as typed (Apple Terminal guide); locating a tab by its `tty` property is the standard technique but the property name was not verified from the dictionary. Ghostty exposes AppleScript too (ghostty.org/docs/features/applescript, not examined).

5. RECOMMENDATIONS (primary + fallback per CLI)
======================================================================
CLAUDE CODE — Primary: user-level `~/.claude/settings.json` hooks of `type:"http"` to the daemon's localhost API (SessionStart/SessionEnd → roster + terminal identity from env; UserPromptSubmit → working; PermissionRequest → question, daemon may answer with decision; PreToolUse[AskUserQuestion] → card with choices, answer via allow+updatedInput; Elicitation → card; Stop → ready + last_assistant_message → TTS; StopFailure → error; Notification[idle_prompt] → idle; MessageDisplay optional for streaming TTS) plus a chained `statusLine` command for heartbeat/model/cost/session_name. Orders: bundle an MCP "channel" server in the daemon (`claude/channel` + permission relay) and launch operator sessions via a daemon-provided wrapper (`claude --dangerously-load-development-channels server:deck` until allowlisted); if the session lacks the channel, fall back to terminal injection using the identity captured at SessionStart (tmux → iTerm2 → Terminal.app → CGEvent). Cross-check roster with `claude agents --json` polling (2-5 s). For GUI-native sessions, host via stream-json control protocol (`--permission-prompt-tool stdio`) or the Agent SDK.
CODEX — Primary (full parity incl. choice questions and orders): daemon runs `codex app-server --listen unix://<path>` (unix socket; ws is "unsupported"), operator TUIs launched by the daemon wrapper with `codex --remote unix://<path>`, daemon connects as a client, `thread/list`+`thread/resume` to subscribe, maps requestApproval/requestUserInput → cards, `turn/steer`/`turn/start` → orders, `item/agentMessage/delta` → TTS. Must verify request-routing with two subscribers (open question 4). Secondary for plainly-launched TUIs: hooks (PermissionRequest allow/deny, Stop last_assistant_message, UserPromptSubmit, SessionStart/End) + `notify` redundancy. Fallback: push `tui.terminal_title = ["activity","project-name","session_id"]` and parse `[ ! ] Action Required` + terminal injection.
GEMINI — Primary: hooks (BeforeAgent, Notification/ToolPermission, AfterAgent.prompt_response, SessionStart/End) for state/ready/TTS; permission answers and orders via terminal injection; or daemon-hosted `gemini --acp` when the GUI is the surface. Fallback: title glyphs ◇/✋/✦ (on by default) via AX or tmux `pane_title`.
DECK MAPPING — `agent.kind` from hook `hook_event_name` source (claude/codex/gemini), `agent.title` from Claude `session_name`/statusLine or Codex thread `name`/notify `input-messages[0]` or Gemini `prompt`; `card type:q` ≤4 choices×32 B: permission → ["Allow","Allow always","Deny"] with `rec`; AskUserQuestion → one card per question (options ≤4 fits), free-text via PTT → `answers[question]=<STT text>`; Codex requestUserInput isOther → PTT; `reply` ≤200 B from last_assistant_message; `card type:r` "suggested next steps" have NO source in any CLI (daemon heuristic on last reply or leave empty). Question chime should be driven by PermissionRequest/PreToolUse, never by Notification (6 s late).

## Options
### Claude Code — hooks (HTTP type) + statusLine as the primary state/question/answer channel; channels MCP server for orders; terminal injection fallback
- pros: Zero per-project config (user-level settings.json); immediate PermissionRequest/PreToolUse/Stop events; last_assistant_message for TTS without transcript parsing; daemon can answer permission prompts and AskUserQuestion choices from the deck by holding the HTTP hook request; SessionStart hook env captures TMUX_PANE/ITERM_SESSION_ID/TERM_SESSION_ID for later injection and window focus; channels give a supported text-injection path with dual-path permission relay.
- cons: Hooks block Claude while pending (dialog suppressed until the daemon responds or times out); channels are research preview, require --channels/--dangerously-load-development-channels at launch, claude.ai/Console auth and org opt-in; channel mid-turn semantics undocumented; only one statusLine command per settings level (must chain user's); Claude Desktop-hosted sessions unverified for hook answering.
- recommendation: Primary for Claude Code. Fallback: `claude agents --json` polling for roster/liveness and tmux/iTerm2/Terminal.app keystroke injection for orders when the session lacks the channel.
### Claude Code — daemon-hosted sessions via stream-json control protocol (`claude -p --input-format stream-json --output-format stream-json --permission-prompt-tool stdio`) or the Agent SDK
- pros: True programmatic input (queued user messages, interrupt), can_use_tool control requests deliver permission prompts and AskUserQuestion with choices directly to the daemon; pending_permission_requests redelivery on reconnect; session files remain resumable with `claude --resume`.
- cons: The operator's terminal is no longer the surface — the gpui GUI must render the transcript; `--permission-prompt-tool stdio` and the exact JSON shapes are only community-documented (the SDK reference documents the envelope); Node SDK dependency if not speaking the protocol directly.
- recommendation: Use for GUI-launched sessions and for the gpui client's own 'new agent' flow; not for sessions the operator started in a terminal.
### Codex — daemon-owned `codex app-server --listen unix://…` with operator TUIs attached via `codex --remote unix://…`; daemon subscribes with thread/list + thread/resume
- pros: Only path that exposes choice questions (item/tool/requestUserInput), approval requests with command/cwd/reason, streaming agentMessage deltas, turn/completed failure status, and mid-turn `turn/steer` / idle `turn/start` orders; thread/status activeFlags waitingOnApproval maps to the deck states; multi-subscriber semantics implied by thread/unsubscribe wording.
- cons: Requires launching Codex through a daemon wrapper; WebSocket listener is 'experimental and unsupported' (use unix socket); undocumented which subscriber receives server-initiated requests when the TUI and the daemon are both attached; experimentalApi gating for requestUserInput; not applicable to the Codex Desktop app.
- recommendation: Primary for Codex when full parity is wanted; verify request routing with two subscribers first.
### Codex — hooks (PermissionRequest/Stop/UserPromptSubmit/SessionStart/End) + notify agent-turn-complete for plainly launched TUIs
- pros: Works with any `codex` launch; PermissionRequest allow/deny from the deck; Stop and notify both give last_assistant_message for TTS; user-level config only.
- cons: No user-question event (requestUserInput is app-server only); PermissionRequest cannot rewrite input; no error event; SessionEnd only after 30 min idle; hooks regressed in Codex Desktop 0.129; hook env inheritance undocumented (terminal identity capture uncertain); no text-injection path.
- recommendation: Secondary/fallback for Codex; combine with title parsing (`tui.terminal_title` incl. `session_id`, `[ ! ] Action Required`) and terminal injection.
### Gemini CLI — hooks (BeforeAgent/Notification ToolPermission/AfterAgent/SessionStart/End) with terminal injection, or daemon-hosted ACP (`gemini --acp`)
- pros: Hooks on by default; AfterAgent.prompt_response gives the reply text; ToolPermission notification is immediate; title glyphs ◇/✋/✦ on by default make Gemini the most title-parseable CLI; ACP gives deterministic permission answers (allow_once/allow_always/reject_once/reject_always) and session/prompt injection when daemon-hosted.
- cons: No AskUser-style question tool (no choices to render); no error hook; permission answering from hooks unverified (BeforeTool decision may bypass); ACP mode means the GUI is the surface; no way to inject into a running interactive session.
- recommendation: Primary: hooks for state + terminal injection for answers/orders; ACP for GUI-hosted sessions; title glyphs as fallback.
### Uniform ACP driver layer (claude-agent-acp, codex-acp, gemini --acp) inside the daemon
- pros: One JSON-RPC schema for session/new, session/prompt, session/cancel, session/request_permission and agent_message_chunk across all three agents; adapters maintained under agentclientprotocol.
- cons: Daemon-hosted only (operator terminals not the surface); Node adapters for Claude/Codex; AskUserQuestion/requestUserInput mapping through ACP not verified; adds a protocol layer between the daemon and each vendor's richer native API.
- recommendation: Consider only for the GUI-hosted path; native hooks/app-server remain necessary for terminal-launched sessions.
### Window-title parsing + macOS Accessibility/tmux introspection as the generic roster source (the spec's Hyprland-style assumption)
- pros: Works with any CLI or launch method; Gemini and Codex titles carry state glyphs; tmux pane_title/pane_current_command/pane_pid are cheap to poll; AX can also focus the window for the deck's channel switch.
- cons: Claude's title has no state glyph and changes only per topic; requires Screen Recording (kCGWindowName) or Accessibility (AX) permission; polling latency 250-1000 ms; no question text/choices, no reply text (capture-pane output is TUI-redraw noise); brittle to title format changes.
- recommendation: Fallback only, and for window focus mapping; never the primary state source on macOS.
