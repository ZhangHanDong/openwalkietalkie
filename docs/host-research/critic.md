## Options
### Two front doors for the open API: Unix socket (JSON-RPC, peer-cred auth) + loopback HTTP (bearer token) over one internal event bus
- pros: Satisfies Claude HTTP hooks (mandatory http URL), Codex/Gemini command hooks via a tiny helper, gpui GUI and scripts over the socket, deck-mcp stdio child over the socket; token in the hook URL/header lives in the user's 0600 settings files; Origin/Host checks block browser CSRF.
- cons: Two listeners to secure and version; the hook helper binary still needs a stable non-translocated path (openmicrokbd refuses AppTranslocation).
- recommendation: Adopt; resolves the transport contradiction between the openmicrokbd and agent-cli-hooks reports.
### Fold icon sync (channel 3) into the deck daemon; one HID reader/writer per host
- pros: Only one process can honour the 8 ms pace and the shared 64-entry firmware queue; removes the second LaunchAgent and lock file.
- cons: Daemon must carry the Codex config.toml watcher and OMD2 codec from host/src; migration/uninstall of the existing com.conol.openmicrodial.icon-sync agent needed.
- recommendation: Adopt.
### Daemon as a signed helper inside the .app bundle registered with SMAppService, carrying an Info.plist with microphone/speech-recognition usage strings
- pros: Stable TCC identity for mic, speech, Accessibility and Automation grants; survives Sparkle updates; user-visible in Login Items; answers the openmicrokbd open question on daemon placement.
- cons: macOS 13+ only; the LaunchAgent cannot own a tray icon (GUI process still needed for that); first-run permission prompts must be driven by the GUI calling the daemon.
- recommendation: Adopt for macOS; keep tools/install-host.sh only as a dev fallback.
### Audio policy: open the deck mic (HFP) only during the PTT hold; play chimes/TTS to the A2DP output selected by UID; software gain implements the Speaker/Mic settings
- pros: Restores A2DP quality between utterances, no system-volume side effects, deterministic mixer priorities (question > ready > chatter, PTT preempts).
- cons: SCO bring-up latency may clip the first syllables (unmeasured); TTS played within ~1 s after PTT release goes through SCO; A2DP start latency may clip the first chime.
- recommendation: Adopt provisionally; measure SCO/A2DP switch latency on hardware before freezing (open question).
### STT engine: Apple Speech (SFSpeechRecognizer/SpeechTranscriber) for English on-device, with an opt-in server mode for zh-CN, or a bundled local model (whisper.cpp / sherpa-onnx) for offline Chinese
- pros: Zero-dependency English on this Mac; Chinese works today via Apple's server recognizer.
- cons: zh-CN audio leaves the machine with Apple Speech; local models add binary size/CPU; the Settings face has no language row so locale must live in daemon config/GUI.
- recommendation: Decide after the (missing) voice report is reconciled with the verified availability facts.
