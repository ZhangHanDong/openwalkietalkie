OpenWalkieTalkie 0.4.0 adds more room for firmware, an on-device recovery screen, faster USB updates, and Chinese text on the deck.

## What changed

- Use 15.75 MiB of the 16 MiB NOR flash for application code and assets while preserving the flash table, bootloader, and both Bluetooth storage regions. Firmware runs directly from flash again after the clock-configuration fix.
- Upgrade compatible Rev A and Rev B devices from the old recovery bootloader through the Mac app. The guided sequence installs a temporary updater, backs up and replaces the bootloader, verifies it by reading it back, and installs the final firmware.
- Show recovery instructions, firmware transfer progress, completion, and errors on the device display.
- Use sparse transfers and pipelined USB bulk on the new bootloader. The initial transfer through an old bootloader still uses HID and takes several minutes; flash erase/write time also affects the total.
- Render simplified and traditional Chinese with a bundled Noto Sans CJK font, and show Codex questions and answers as readable text instead of protocol envelopes.
- Include Codex Desktop integration and the Bluetooth signal-strength indicator added since 0.3.0.
- Bundle both boards' firmware and a verified manifest in the app, so firmware installation also works offline. Keep the device About version aligned with the firmware build.

## Upgrading from 0.3.0

Install the signed and notarized macOS app for Apple Silicon or Intel, or use **Check for Updates**. macOS 13 or later is required. Then connect one deck by USB-C and open **Service → Updates → Check firmware**.

**This upgrade can replace the bootloader. Keep USB-C power connected and the Mac awake until the app reports success. Losing power during bootloader replacement can prevent both normal startup and USB recovery and require hardware repair.** The app requires explicit acceptance of this warning. Do not perform a power-loss test during that stage.

Use the GUI for the migration. Do not manually flash a `bootstrap` or `recovery` image as the application, mix board revisions, or write the padded application binary across Bluetooth storage with a generic flash tool. The updater preserves those regions and does not rewrite the flash table.

After completion, the app should report **0.4.0-openwalkietalkie**, and the device About page should show **0.4.0 · Rev A** or **0.4.0 · Rev B**. A Chinese upgrade guide is included as `README.zh-CN.md` and inside the DMG.

## Validation status

Both board variants build and pass software checks. An earlier 0.3.1 candidate completed the full original-0.3.0-to-new-bootloader GUI migration on Rev A in about 5½ minutes; its recovery bootloader bytes are identical to 0.4.0. The final 0.4.0 GUI rerun was blocked by local desktop automation before flashing, so it is not recorded as a completed hardware test. A shipped Rev B was unavailable: its full migration, panel behavior, and preservation of pairing/settings still need hardware validation. No device audio test was performed in this session.

Release assets include both macOS packages and signed update feeds, board-specific application/bootstrap/recovery images, debug ELFs, the updater manifest, SHA-256 checksums, and build attestations.
