# OpenWalkieTalkie 0.4.0 升级说明

本版本提供 Apple Silicon 和 Intel Mac 安装包，要求 macOS 13 或更新版本。正式 DMG 使用 Developer ID 签名并经过 Apple 公证；请从本项目 GitHub 的 v0.4.0 Release 下载，核对 SHA256SUMS。不要使用此前未公证的内部测试 DMG 代替正式版本。

## 从 0.3.0 升级

1. 在 Mac 应用内使用 **Check for Updates**，或安装匹配 Mac 架构的 0.4.0 DMG。确认应用与 Service 页面中的 deckd 均为 0.4.0。
2. 用稳定的 USB-C 数据线直接连接一台设备，保持供电并让 Mac 保持唤醒。
3. 打开 **Service → Updates → Check firmware**，核对 Rev A / Rev B、USB 序列号及目标版本 0.4.0。
4. 点击 **Update firmware…**。旧 Bootloader 会触发 **Bootloader update — power must stay connected** 警告；可以先按 Cancel 检查取消不会开始升级。
5. 阅读警告后点击 **I understand — update device**。应用会自动安装临时升级程序，备份并替换 Bootloader，完整读回校验，再安装正式固件。
6. 等到 **Firmware updated. Your deck is ready.**，确认版本为 **0.4.0-openwalkietalkie**，设备 About 显示 **0.4.0 · Rev A** 或 **0.4.0 · Rev B**。

**写入 Bootloader 时断电可能导致设备无法启动，也无法通过 USB 恢复，需要硬件维修。整个升级期间请勿拔线、关机或让电脑休眠。不要在 Bootloader 写入阶段人为测试断电。**

第一次通过旧 Bootloader 传输临时升级程序仍使用 HID，需要数分钟；新 Bootloader 支持稀疏传输和 USB bulk，Flash 擦写也需要时间。首次迁移的总耗时不能只按 12 Mbps USB 标称速度估算。

## 版本内容

- 16 MiB NOR 中有 15.75 MiB 可供应用代码与资源使用，保留分区表、Bootloader 和两个蓝牙存储区。
- 时钟修复后直接从 Flash 执行；无需再把应用代码整体复制进 PSRAM。
- 恢复模式显示说明、升级进度和错误状态。
- 支持简繁中文显示；Codex 问答显示易读内容，不再直接展示协议包装。
- 包含 Codex Desktop 集成、蓝牙信号强度显示，以及应用内完整固件清单和离线升级支持。

正常升级仅操作 GUI。不要手动把 bootstrap 或 recovery 当作应用烧录，不要混用 Rev A / Rev B 镜像，不要用通用工具把带填充的 bin 连续写过蓝牙存储区。GUI 会跳过这些区域，且不会重写分区表。

## 验证范围与团队检查

两个板型均完成构建与软件验证。此前 0.3.1 候选版本在 Rev A 上完成了原始 0.3.0 到新 Bootloader 的完整 GUI 迁移，约 5 分半；使用相同的恢复程序源码，但 CI 重新构建的正式 Bootloader 字节不同，未在该次测试中烧录。最终 0.4.0 GUI 重测在开始刷写前被本机桌面自动化故障阻断，不能记为通过。没有可用的已出货 Rev B 真机，因此该板型的完整升级、显示方向及配对/设置保留仍待团队验证。本轮未进行设备音频测试。

请记录板型、USB 序列号、Mac 型号与系统版本、升级前后版本、各阶段耗时、警告与取消行为、恢复界面方向、升级后的按键/旋钮/中文显示、配对保留和正常重启。升级失败时保持供电，保存 GUI 完整错误与 Service → Open log 中的日志；若提示不要重启，不要自行断电。

Bootloader 备份位置：`~/Library/Caches/OpenWalkieTalkie/firmware/bootloader-backups/`。不要上传蓝牙配对数据。
