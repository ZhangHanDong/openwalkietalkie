OpenWalkieTalkie 0.5.0 fixes Codex Desktop connectivity and missing short replies, adds support for two alternative flash chips, and includes factory programming images.

## What changed

- Connect Codex Desktop to the shared local Codex service explicitly. Desktop's default plugin configuration could previously make the launcher fall back to a private server, leaving its tasks invisible to OpenWalkieTalkie.
- Detect compatible installations named either ChatGPT.app or Codex.app. The launcher uses the bundled CLI, reuses the existing daemon, and asks you to quit an already-running Desktop session before relaunching it.
- Restore replies from tasks that finish before OpenWalkieTalkie subscribes to a newly created Desktop thread.
- Support Puya PY25Q128HA-SUH-IR (C5354566) and GigaDevice GD25Q128ESIGR (C2928891), alongside Winbond W25Q128JVSIQ (C97521), in the firmware's settings/bond and bootloader flash writers. Unknown or unstable JEDEC IDs are rejected before writes.
- Include a factory ZIP with separate full 16 MiB Rev A and Rev B images, Chinese programming instructions, a component manifest, and a standalone checksum verifier. The images contain the same firmware and recovery binaries as this release, plus a fresh flash table and empty unit storage.

## Update and enable Codex Desktop

Install the signed and notarized macOS app for Apple Silicon or Intel, or use **Check for Updates**. macOS 13 or later is required. Confirm that both the app and its service report 0.5.0.

Open **Integrations → Codex Desktop** and install or repair the integration. When your Desktop tasks are idle, quit Codex Desktop / ChatGPT, then open `~/Applications/Codex with OpenWalkieTalkie.app`. This small launcher starts your installed Desktop app with the shared connection; use it for future launches too. Opening the original app directly does not enable this integration. If the installed Desktop build lacks the required connection mode, the launcher reports an error.

Connect one deck by USB-C and open **Service → Updates → Check firmware** to install firmware 0.5.0. The partition layout and recovery protocol remain unchanged from 0.4.0. Devices already using recovery protocol 2 receive a normal application update.

**Devices still on the old bootloader need the guided migration. Keep USB-C power connected and the Mac awake throughout. Losing power while replacing the bootloader can prevent startup and USB recovery and require hardware repair.** Read and accept the app's warning before proceeding. Do not manually install bootstrap or recovery files as application firmware.

The factory ZIP is for blank-board provisioning. It overwrites the whole flash, including settings and pairing data; use the GUI updater for existing devices. A Chinese upgrade guide is included as `README.zh-CN.md` and inside each DMG.

## Validation status

The Desktop launcher and transport regression tests pass. A live Desktop session on the development Mac connected to the shared service, and its `DESKTOP-LINK-OK` reply appeared in the OpenWalkieTalkie GUI. USB delivery to the attached Rev A was healthy; a final visual confirmation on the physical display was not recorded.

Both board variants pass software checks. The preceding 0.4.1 development firmware with the same flash-chip support completed an old-bootloader migration on the existing Rev A. The CI-built 0.5.0 artifacts have not been flashed in that hardware test. A shipped Rev B, boards populated with the alternate flash chips, and blank-board factory programming still need physical qualification. No device audio test was performed.

Release assets include both Mac packages, signed update feeds, board-specific application/bootstrap/recovery images, ELFs, the factory ZIP, updater manifest, SHA-256 checksums, and build attestations.
