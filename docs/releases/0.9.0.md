OpenWalkieTalkie 0.9.0 brings 48 kHz USB speaker playback, reduces encoding and reconstruction artifacts in the 16 kHz path, and reminds you when unused manual usage resets are about to expire.

## Clearer USB speech

- The Mac service now sends speaker audio at **48 kHz over USB** when the connected firmware advertises support. Older firmware falls back to 16 kHz automatically.
- Speaker EQ stays enabled at both rates. Switching between USB and BLE, or releasing push-to-talk, reopens playback at the negotiated rate.
- The firmware accepts high-rate audio only after an explicit USB start and buffers enough packets for amplifier startup. BLE speaker audio and microphone capture remain at **16 kHz**.
- The 16 kHz host encoder searches alternative ADPCM predictor paths to reduce quantization error, retaining the original result whenever it is better. Firmware uses a band-limited FIR interpolator to reconstruct 16 kHz playback at the 48 kHz DAC rate.

In a matched English TTS comparison on Rev A with EQ enabled, the listener reported clearer words and less noise at 48 kHz. Both rates completed without gaps, underruns, queue drops, or sequence errors. The revised 16 kHz encoder reduced squared encoding error by about 30% on that passage; complete audible hiss removal in the revised 16 kHz path has not been confirmed. BLE 48 kHz playback is not enabled or claimed as validated.

## Reminders for expiring manual resets

The Mac app's Usage page and the deck's Usage face show a small amber tip below a provider's weekly bar when unused, redeemable reset credits expire within **72 hours**. For example: **“2 resets expire in 1d 6h.”**

This is separate from the normal weekly allowance countdown. The reminder uses the nearest credit expiry, counts only grants sharing that deadline, and disappears when credits are spent or expire. Unsupported or unavailable provider data produces no reminder. Account changes clear the previous account's credits, and disconnected views hide the tip. The feature does not redeem credits automatically.

## Install and factory packages

Install the signed, notarized macOS app for Apple Silicon or Intel, or choose **Check for Updates**. macOS 13 or later is required. Connect the deck over USB-C and use **Service → Updates → Check firmware** to install 0.9.0. Update both the service and firmware to enable 48 kHz USB playback and both sides of the 16 kHz improvements.

The app, deckd, and device firmware report 0.9.0. Recovery protocol 2, flash partitions, settings, and Bluetooth pairing are unchanged by a normal update; older recovery versions use the existing guided migration. Rev A retains RAM execution and Rev B retains NOR execution.

Factory ZIPs remain board-specific: `OpenWalkieTalkie-0.9.0-factory-hw-a.zip` and `OpenWalkieTalkie-0.9.0-factory-hw-b.zip`. They contain full-chip images and Chinese SPI NOR programming instructions. Factory images overwrite settings and pairing; use the app updater for existing devices.

## Validation

Rev A development firmware was flashed over USB. Controlled music and speech comparisons completed without transport errors, and normal daemon playback was confirmed to open at 48 kHz after restarting the updated service. Rev B audio has not been field-tested in this session.

Automated coverage includes sample-rate negotiation and fallback, USB/BLE transitions, push-to-talk release, ADPCM state continuity and error, FIR frequency response, reset-credit filtering and expiry boundaries, account changes, protocol compatibility, and Usage rendering. The release pipeline checks all board builds, host tests and lint, production and migration packages, notarized Mac packages, factory images, and checksums before publication.
