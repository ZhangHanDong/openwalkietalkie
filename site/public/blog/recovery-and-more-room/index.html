OpenWalkieTalkie v0.4.0: recovery on screen, room to grow

October 18, 2026App and firmware update

OpenWalkieTalkie 0.4.0 gives the deck more space for features and makes firmware recovery visible on the device itself. It also adds Chinese text support and clearer Codex questions and answers.

More of the flash is available to the application

The 16 MiB NOR flash now provides 15.75 MiB for application code and assets. The flash table, bootloader, and both Bluetooth storage regions keep their reserved space. Chinese fonts live in the upper application bank, leaving more room for code in the lower bank.

With the clock configuration corrected, the firmware executes directly from NOR flash again. It no longer copies the whole application into PSRAM at startup.

A recovery screen and faster USB updates

The new bootloader shows recovery instructions, transfer progress, completion, and errors on the deck’s display. Updated devices can use sparse transfers and pipelined USB bulk, avoiding writes to padding and preserving the Bluetooth storage regions.

The first upgrade from an old bootloader still begins with a HID transfer of a temporary updater. That stage takes several minutes. Later stages can use the new transport, but flash erase and write time still contribute to the total.

Upgrading from 0.3.0

Install the 0.4.0 Mac app, connect one deck with a USB-C data cable, and open Service → Updates → Check firmware. Check the board revision and serial number before continuing.

This upgrade can replace the bootloader. Keep USB-C power connected and the Mac awake until the app reports success. Losing power during bootloader replacement can prevent both startup and USB recovery and require hardware repair. The app displays this warning and requires explicit confirmation before migration.

The app installs a temporary updater, backs up and replaces the bootloader, reads it back to verify the write, then installs the final firmware. Use this guided flow rather than manually flashing the bootstrap or recovery files. The updater does not rewrite the flash table and skips the Bluetooth storage regions.

After completion, the device About page should show 0.4.0 · Rev A or 0.4.0 · Rev B. The version label now follows the firmware build automatically. Both board variants and their verified manifest are bundled with the app, so firmware updates can also work offline.

Chinese text and clearer agent conversations

A bundled Noto Sans CJK font adds simplified and traditional Chinese coverage. Codex clarification questions and answers appear as readable headings, question context, and answer text, instead of showing their transport envelope. This release also includes the Codex Desktop integration and Bluetooth signal-strength indicator added since 0.3.0.

What has been tested

Both board variants build and pass software checks. An earlier 0.3.1 candidate completed the full original-0.3.0-to-new-bootloader GUI migration on Rev A in about five and a half minutes. It used the same recovery source. The CI release rebuild produces different bootloader bytes and has not been flashed in that test.

The final 0.4.0 GUI rerun was blocked by local desktop automation before flashing. A shipped Rev B was unavailable, so its complete migration, display behavior, and pairing/settings preservation remain to be checked on hardware. These are pending checks, not completed validation. No device audio test was performed in this session.

Get v0.4.0

Use Check for Updates or download the signed and notarized Mac app for Apple Silicon or Intel. macOS 13 or later is required.

The GitHub release includes firmware, checksums, and a Chinese upgrade guide. The same guide is included inside the DMG.
